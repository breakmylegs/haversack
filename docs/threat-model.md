# Threat model

Seeded from build prompt section 18 in slice 1 and extended every slice. Each entry has a mitigation or an accepted risk signed off by the owner before v1.0.0.

Status values: **planned** (mitigation designed, not built yet), **partial** (some of it built), **in place** (built and tested), **accepted** (risk accepted by the owner).

| ID | Threat | Mitigation | Status | Since |
|---|---|---|---|---|
| T1 | Token theft from disk | Mode 0600 token files, no logging, minimal scopes | in place (slice 6): `onedrive-token.json` written 0600; scopes `Files.ReadWrite.AppFolder offline_access` only, so a stolen token reaches only `Apps/Keepsake`; tokens and codes are redacted from logs (tested in `tests/test_app_cloud.py`); diagnostics exports never read the token file | 1 |
| T2 | Device code phishing | Flows start only from a user action and show the app name and expected domain | in place (slice 6): sign-in starts only from the Settings button; the verification page must be HTTPS on `microsoft.com` or `live.com`; the screen tells the user to check for `microsoft.com` and the name Keepsake | 1 |
| T3 | Malicious or wrong manifest paths | Root confinement, traversal rejection, preview before first sync | in place (slice 4): `resolve.to_logical` rejects unknown placeholders, `..`, `.`, absolute paths and drive letters; `resolve.scan` keeps every match inside its root after `realpath` and never follows symlinked folders; `resolve.safe_base` refuses over-broad `base` roots; the Games page previews files before any sync. Tests in `tests/test_resolve.py` (symlink cases run on device) | 1 |
| T4 | Zip slip during restore | Validate every entry before extraction | in place (slice 5): `snapshot._check_zip` requires every entry to be listed in validated metadata, a regular file, unencrypted, of the stated size and below a 1000:1 compression ratio; extraction joins inside its base with traversal checks and verifies each SHA-256. Tests with hand-crafted hostile zips in `tests/test_snapshot.py` | 1 |
| T5 | Cloud tampering or corruption | Hash verification of blobs and metadata. Encryption is a later option | partial (slice 5): metadata is validated (paths, kinds, `contentHash` recomputed against the file list); blobs are checked against `blobSha256` and per-file hashes before any restore; uploads are verified by the hash the store reports, or by re-download. Metadata itself is unsigned; an attacker with write access to the cloud folder could publish a consistent but malicious snapshot, limited by root confinement (T3, T8). Encryption remains out of scope for v1 | 1 |
| T6 | A game left frozen | Watchdog, `finally` blocks, resume on start | in place, used by the slice 8 launch gate (release in `finally`, tested with a forced failure and a timeout); originally for the slice 1 freeze test: `freeze.Freezer` persists PIDs before stopping, fails closed if it cannot persist, runs a 30 second watchdog thread independent of asyncio, keeps an in-memory copy if the state file is corrupt, and `KeepsakeApp.start` resumes leftovers. Tested in `tests/test_freeze.py` and `tests/test_app.py` | 1 |
| T7 | The wrong process frozen | Environment matching, user ownership, ancestry checks | in place for the freeze test: `procs.find_game_processes` matches `STEAM_COMPAT_DATA_PATH`, `SteamGameId` or `SteamAppId`, filters by UID, never selects the plugin or its ancestors; resume checks process start time so a reused PID is never signalled | 1 |
| T8 | Writes outside the allowlist | Central path validation used by every write | in place (slice 5): restore resolves every target, staging and backup path with `safepath.join_within` against its logical root before writing, re-checks parents before each move, and stages beside the save folder only; settings and store writes go through `safepath` too | 1 |
| T9 | Secrets or personal data in logs or diagnostics | Redaction tests | in place: `redact.redact` on every log record and on the diagnostics export; non-stock usernames hidden; tests in `tests/test_redact_log.py` and `tests/test_diagnostics.py` | 1 |
| T10 | Malicious update via compromised repository or release | Protected tags, SHA-256 checks, signature verification. **Changed by ADR-0004:** no CI, so releases are built locally from a deterministic zip and the minisign signature with a key held only by the owner becomes the main control; anyone can rebuild a tag and compare hashes | partial: `main` protected and `v*` tags immutable (ADR-0005), Actions disabled. Slice 2: `scripts/release.py` builds deterministic zips and signs `SHA256SUMS` when a minisign key is set; the updater requires a `SHA256SUMS` entry and Decky checks the zip against it. **Gap:** the plugin does not yet verify the minisign signature (build prompt "Should"), so a compromised GitHub account could publish a matching zip and `SHA256SUMS`. Planned for slice 12 | 1 |
| T11 | Personal data committed to the public repository | Synthetic fixtures, `.gitignore`, pre-commit secret scan | in place: `scripts/secret_scan.py` (plain in-repo script, no third-party scanner), `.githooks/pre-commit`, `pnpm run check`, optional local denylist, `.gitignore` for settings, tokens and diagnostics | 1 |
| T12 | GitHub API rate limits | Caching and quiet failure | in place: at most one automatic check a day, ETag `If-None-Match`, 403 and 429 keep the cache and report quietly, unauthenticated requests only (`keepsake.update`, tests in `tests/test_update.py`) | 1 |
| T13 | Two devices racing | Create-only writes and fork detection | in place: create-only on both stores, tested with racing writers in the shared store contract; OneDrive uses upload sessions with `conflictBehavior: fail`; slice 7 detects forks after every push and at every launch, and a push racing a pull is a simulator scenario | 1 |
| T14 | Clock skew | Hashes and parents decide | in place (slice 7): the decision table compares content hashes and parent links only; the two-device simulator runs one device three days behind | 1 |
| T15 | A registry merge corrupting a prefix | Backup, key-level scope, re-parse validation | planned (slice 11) | 1 |

## Slice 1 additions

| ID | Threat | Mitigation | Status |
|---|---|---|---|
| T16 | Diagnostics export reveals the game list or device facts if shared | Export stays in the device settings folder, is redacted, and the slice report summarises it with generic names. Peter decides what to copy off the device | in place |
| T17 | Development deploy script runs `sudo` on the device | Development only, prompts for the password interactively, never stored; the plugin itself has no root flag | accepted for development; owner to confirm |
| T18 | Decky's installer reports installs to the Decky store server when a version string other than `dev` is passed | ADR-0002: Keepsake passes `dev`, so no store POST is made | in place (slice 2) |
| T20 | Device test runner executes repository code on the device | Runs as the device user in a temporary folder under `~/.cache`, deleted afterwards; never touches the installed plugin or Decky; only run by the owner against their own device | accepted for development |
| T21 | Network calls to hosts outside the allowlist, including through redirects | `keepsake.net` allows only HTTPS to allowlisted hosts, checks every redirect target, rejects credentials in URLs and caps response size | in place (slice 2), tests in `tests/test_net.py` |
| T22 | An update while a sync job or game session is running corrupts state | `JobTracker` guard in `Updater.prepare`; "Update when idle" waits for the idle event | in place (slice 2) |
| T23 | A rollback deletes settings written by the newer version, or the older version writes data it does not understand | Unknown settings keys are preserved on write; a newer `schemaVersion` opens read-only safe mode that never writes | in place (slice 2), tests in `tests/test_settings.py` |
| T24 | Release signing key leaked or committed | Key kept outside the repository; `.gitignore` blocks common key filenames; secret scan flags minisign secret key headers | in place, owner to keep the key offline |
| T25 | Discovery results (absolute paths, per-device app IDs, Steam account id3) leak into cloud data or logs | Discovery output stays on the device and is never uploaded (principle 10); account and persona names in `loginusers.vdf` are never read into results; scan logs record counts only | in place (slice 3), test `test_results_carry_no_account_names` |
| T26 | Wrong prefix chosen for a shortcut, so a later restore writes into another game's prefix | Prefix from the shortcut's own app ID, `pfx` must exist, base library first; runtime cross-check records mismatches; a mismatch or an unreadable mismatch file blocks sync (fail closed) | in place (slice 3); enforced by sync from slice 7 |
| T27 | Tampered or malformed manifest download (compromised upstream or transit) | HTTPS to an allowlisted host; streaming subset parser that skips unsupported entries; size cap (64 MB); an empty index never replaces a good one; manifest paths are confined to logical roots (T3), so the worst case is wrong or missing files in the preview, not writes elsewhere | in place (slice 4); accepted that the manifest is unsigned |
| T28 | Custom paths chosen in the file picker point outside the game's folders | Converted to root plus relative path; refused unless inside one of the game's roots; relative paths validated | in place (slice 4), tests in `tests/test_gameconfig.py` |
| T29 | A restore interrupted by power loss or a crash leaves a mix of old and new save files | Journalled restore with staging and backups beside each root; immediate rollback on errors; `restore.recover()` on start and before every restore; property test crashes at every step | in place (slice 5), `tests/test_restore.py` |
| T30 | A bad save (game bug, wrong match, empty folder) overwrites good cloud history | Safety gates quarantine suspicious snapshots locally; snapshots are immutable; retention never prunes heads, bases, pins, manual or recent snapshots; property test over random histories | in place (slice 5) |
| T31 | A restore replaces local progress the user wanted | A verified local pre-restore snapshot before every restore, restorable with "Undo to this" | in place (slice 5) |
| T32 | Bearer token leaked to a non-Graph host (upload URL, download redirect, a hostile redirect) | `net.request` never follows redirects; the token is added only for Graph calls; upload and download URLs get no `Authorization`; every URL is checked against the allowlist (dot-boundary suffix match) and a disallowed host is refused, not retried | in place (slice 6), `tests/test_graph_store.py` |
| T33 | A corrupted or truncated upload is accepted | Reported SHA-256 or QuickXorHash must match, else the engine re-downloads and compares SHA-256 | in place (slice 6) |
| T34 | Refresh token revoked or expired | `sign-in-needed` health state; snapshots fail without touching local files; queued pushes wait (slice 7) | partial (slice 6) |
| T35 | Sync silently overwrites progress on one device with another's | Conflicts whenever both sides changed; restores only when the local files equal the base or are empty; every restore takes a verified pre-restore snapshot; conflict choices keep and pin the loser; randomised no-loss invariant over two devices | in place (slice 7), `tests/test_sync.py`, `tests/test_sync_invariant.py` |
| T36 | A conflict that keeps coming back, or a fork that never closes | Both conflict choices publish a merge whose parents are every head | in place (slice 7) |
| T37 | A launch check that times out restores under the running game | After a timeout the abandoned pull treats the game as running, so it cannot start a restore; tested (`test_timeout_releases_game_and_late_pull_cannot_restore`) | in place (slice 8) |
| T38 | The strict wrapper loses or corrupts the user's launch options | Original saved before any change and never overwritten; restored exactly; round-trip tested | in place (slice 8) |
| T39 | A stale ready file releases the strict gate without a check | One-off token per launch; the gate only accepts a ready file with its own token, validated as hex | in place (slice 8) |
| T40 | A wrong automatic cross-device match links two different games | Automatic only with a high score, two strong signals, a clear lead and an unused key; shown with its evidence and changeable; a wrong match still cannot overwrite saves silently (adoption conflict, pre-restore snapshots) | in place, ADR-0011, `tests/test_identity.py` |
| T41 | Identity records leak device details | Only file and folder names, normalised names and relative save folders; no absolute paths, usernames or compatdata IDs | in place, ADR-0011 |
| T19 | Decky's installer extracts the zip with `ZipFile.extractall` | Decky's own responsibility; our release zips are built deterministically by `scripts/package.py` with safe entry names | accepted, noted |
| T56 | A tampered or malformed game config revision in the cloud points sync at the wrong files or breaks a device | Revisions carry only canonical shared fields, validated with the same rules as local settings (no `..`, known roots, glob segments only); foreign, mismatched or newer-schema revisions are ignored; resolved paths stay confined to the game's roots (T3, T28); a wrong path can at worst add or leave out files in a snapshot, which the safety gates and pre-restore snapshots cover | in place (slice 9), `tests/test_configrev.py` |
| T57 | Two devices change a game's shared settings at the same time and one change silently disappears | Concurrent edits are detected (same `basedOn`, different devices); the newest applies and the game page names the other device so the user can check | in place (slice 9), `tests/test_app_ux.py` |
| T58 | The conflict modal is dismissed or mis-pressed into replacing a save | B, background and close all mean "Decide later"; initial focus on "Decide later"; replacing choices need a second press; the loser is still kept and pinned (T35) | in place (slice 9); on-device check pending (A105 to A107) |
| T59 | The setup wizard's dry run changes sync state or files | `SyncEngine.plan` is read-only; a test asserts the state file is byte-identical after every plan | in place (slice 9), `tests/test_sync_plan.py` |
| T60 | Health checks or the diagnostics export reveal the game list | Results stay on the device; the export is written to the settings folder only (as T16) | accepted, as T16 |

## v2 additions (slice C0)

From `docs/build-prompt-v2.md` section 13. The spec numbers these T16 to T29, but v1 already uses T16 to T41, so they are renumbered T42 to T55 (ADR-0014, conflict C6). All are **planned**: C0 adds no code.

| ID | Spec ID | Threat | Mitigation | Status | Slice |
|---|---|---|---|---|---|
| T42 | T16 | Rogue LAN device or pairing interception | Listener off by default and bound to selected interfaces; user-started, time-boxed, rate-limited pairing with a 6-digit code; pinned peers; authenticated encryption with stdlib `ssl` only (ADR-0016) | planned | 16, 17 |
| T43 | T17 | Malicious manifest paths from a peer | Central path validator, canonical relative paths, rejection of absolute paths, `..`, case-only collisions and symlinks resolving outside the root; symlinks never followed | planned | 18 |
| T44 | T18 | A partially transferred game is promoted | Staging, verification against the manifest root hash before an atomic promote, replaced files held until the job completes, rollback | planned | 18 |
| T45 | T19 | Replication overwrites saves | P14 exclusions enforced in the path validator, per-game lock (P19), Saves source checkpoint before send, cross-module invariant test | planned | 13, 18 to 20 |
| T46 | T20 | A Steam shortcut corrupted by API calls | Only `SteamClient` APIs after a user action, originals stored first, every field read back, retries, restore originals on failure (ADR-0015) | planned | 13, 19, 21 |
| T47 | T21 | The loopback web UI attacked by a malicious web page (DNS rebinding, CSRF) | `127.0.0.1` binding, `Host` validation, CSRF tokens, no CORS (ADR-0017) | planned | 23 |
| T48 | T22 | Login token leakage | One-time, short-lived login URLs exchanged for a session cookie; never logged | planned | 23, 24 |
| T49 | T23 | Personal data sent to AI providers | P18 payload rules and a payload-inspecting test (ADR-0019) | planned | 15 |
| T50 | T24 | AI or SteamGridDB key theft | Mode `0600` storage, never sent to the frontend, logs, events or diagnostics; redaction tests | planned | 15, 22 |
| T51 | T25 | A malicious installer executable | **Accepted risk**, to be signed off by the owner: a Wine prefix is not a sandbox. Documented in the README | planned (accepted) | 21 |
| T52 | T26 | The tray persists after the module is disabled or the plugin is uninstalled | Removal on disable and in `_uninstall`, plus a health check for a stale autostart entry | planned | 24 |
| T53 | T27 | Licence contamination from ported code | C0 audit (`docs/advisor-port-audit.md`), escalation before porting, no fixture with third-party content, no CapyDeploy or GPL code (ADR-0013) | partial: audit done, awaiting sign-off | C0, 14 |
| T54 | T28 | Suspend or battery exhaustion mid-transfer | Persistent journal, staging, verification before promote, sleep inhibitor only while transferring, pause below 30 percent battery | planned | 18 |
| T55 | T29 | Firewall guidance misused | Detection only; Keepsake shows a narrow, port-specific command and never runs it | planned | 17 |
